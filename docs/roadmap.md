## Using a Team seat with overages disabled

[#35](https://github.com/markdlabrecque/pi-claude-subscription/issues/35#issuecomment-6513928990) was closed by the maintainer because extra spending is disabled. No before/after usage-pool result was recorded. Treat disabled overages as the account's spending control, not evidence that a particular subscription pool or included-credit pool is being debited.

With overages disabled, an unavailable or exhausted entitlement can block work instead of continuing on billed overages. The provider does not replenish limits or make all models available to every seat. Successful responses, token counts, cache hits and Pi's dollar estimates do not identify the account's billing pool.

The extension also has a **separate API-key switch**, independent of the Team overage setting:

```bash
export PI_CLAUDE_SUBSCRIPTION_API_KEY_FALLBACK=0
export PI_CLAUDE_SUBSCRIPTION_SESSION_MODE=replay
```

The fallback is explicit, not automatic on a 429. Setting it to `1` or `true` routes requests through Pi's Anthropic API provider and `ANTHROPIC_API_KEY`; Team overage settings do not cap that separate API account. A key by itself does not enable fallback, and the CLI path strips API-key/auth-token/provider-switch variables. A provider-scoped environment can override the process setting, so check orchestration configuration as well. Selecting a different native API provider in Pi is outside this switch's protection.

If the billing pool needs to be identified, the remaining check is human account observation with exact Pi, extension and CLI versions recorded. It is not a prerequisite to every reliability fix, and this audit did not access account pages or spend usage. Do not remove or disguise Pi's instructions to influence billing.

## What to watch during the week

- **Loading and version drift.** Confirm that `pi-claude-subscription` actually registers and completes a normal text/tool turn in the installed host. Only SDK 1.4.0 is tested here; a wildcard peer range is not an all-1.x guarantee. CLI flags, reminder formats and stream events can change after an update. Retain a known-working installation as a fallback workflow.
- **Screenshots in long sessions.** Replay carries images in user messages and tool results, and sends every one again with each request. A session with many screenshots can therefore run over the model's context or request limits. A live Pi session on the real CLI was checked in `replay` and `resume`: Claude described an image read with `read`, and the follow-up turn worked. Documents are wire-level blocks and are resent with history, so large files consume context repeatedly.
- **Limits and incomplete answers.** 429s can stop work. The relay permits one upstream Messages request per provider invocation, not one per human prompt or complete tool loop. Pi can retry with another invocation; inspect Pi's retry policy if repeated attempts matter. The CLI's own retries and automatic output-limit continuations are rejected. A `length` stop can require an explicit continuation, and a dropped stream can wait for the 180-second inactivity or 10-minute default request timeout.
- **Extension-specific behavior.** Pi still executes tools, so ordinary custom-tool integrations have a tested path. That does not certify every command, widget, hook or Pi-derived host. `onProviderStreamEvent` observes CLI events rather than raw upstream SSE. Structural relay edits can desynchronize CLI/Pi history; tested generation-parameter edits are narrower.
- **Cache changes.** The two known bugs are fixed. Real instruction/tool changes, dates and changed CLI reminder formats can still miss the cache. A miss consumes more input processing but does not prove a separate account charge. Keep replay unless there is a measured reason to accept resume's local session-state dependency.
- **Diagnostics and privacy.** Leave debug logging off during ordinary work. Debug output can include malformed CLI lines containing prompts or tool arguments. For a failed turn, record versions, error/stop reason and redacted request-count diagnostics rather than credentials or full private transcripts.
- **Platforms.** Linux and macOS are the CI targets. Use WSL on Windows; native Windows support was deliberately dropped, not repaired.

## Opt-in audit implementation from review feedback

The feature was implemented on `feat/local-audit` and is now merged into the v1.4.0 release source. It was not released as v0.4.0. `PI_CLAUDE_SUBSCRIPTION_AUDIT=1` writes privacy-safe metadata under `<extension-root>/.audit/YYYY-MM-DD.jsonl`, independently of the raw debug flag. It covers registration, request starts, observable terminal errors and successful usage/cache/version data on both routes. Unknown usage stays null. No prompts, tool content, credentials or raw stderr/errors enter the files.

The packaged `src/audit-loader-check.mjs` records an explicit SDK load check in the same directory without sending a model request. The #76 branch fix resolves the known import defect for the pinned SDK. Loading cannot be automatically audited by extension code that never loads; use this separate check and inspect host diagnostics for actual Pi startup failures.

Daily files have private permissions, seven-day retention and a 5 MiB daily limit. Write/lock failures warn visibly without replacing the provider result. Hard-killed requests can remain incomplete, and observed process close does not certify every descendant. The full operational limits, commands and verification results are in [local audit logging](local-audit.md). A local verification manifest can describe an earlier candidate; match its fingerprints before relying on it. Directory identities are revalidated after lock waits, but hostile cross-process changes between filesystem syscalls remain outside the portable sink's protection.

The initial candidate was committed as `43c87b0`. Later review reproduced three defects despite its green suite. The revised candidate fixes directory replacement during lock contention, real-SDK API failure metadata and usage observation before throwing CLI hooks. It has 76 focused tests and 587 passing full-suite tests, with the existing loader test still skipped. Typecheck, style and coverage passed. Standalone code review found no concrete code findings in the defect fixes, not approval to merge or certify rollout. No live model or account-billing check ran, and remote CI has not run for this candidate.

## Deliberate non-goals

No Pi 0.52 adapter, native Windows support, Claude Code-owned tools/subagents, automatic API billing fallback, automatic CLI retry/continuation expansion, arbitrary native-provider parity or Git-history erasure is promised. These are policy boundaries, not missing checkboxes to silently restore to the roadmap.
