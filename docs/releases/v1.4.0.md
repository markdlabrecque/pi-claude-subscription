## Release notes

- Adds opt-in local audit logging with correlated request starts and terminal records, bounded usage/cost metadata and explicit standalone loader evidence. Audit remains off by default and never records prompts, tool content, credentials or raw errors.
- Includes audit review fixes for directory replacement during lock contention, API HTTP failure metadata and usage observation before throwing stream hooks.
- Fixes packaged and Git/local loading with the pinned Pi SDK 1.4.0 pair.
- Reports dropped upstream response streams promptly without expanding the one-request cap.
- Uses GitHub source releases only. No npm publication, registry credentials or gallery distribution is required.

Private file permissions, seven-day retention, the 5 MiB daily limit and nonfatal write warnings remain as documented in [local audit logging](../local-audit.md). The portable filesystem implementation cannot prevent hostile cross-process replacement between filesystem syscalls. Use a trusted installation directory. This release does not certify billing pools, arbitrary hosts or live model workflows.

It invokes the packaged standalone loader first with audit off, asserting no ledger exists, then with audit on, asserting a fresh successful `extension_load` with extension and host versions 1.4.0. Both checks use the fake Claude executable for startup probes and send no model requests. Temporary ledgers and host directories are removed afterward.

Synthetic audit suites cover correlated start/terminal records, off mode, private directory/file permissions, retention/size limits and nonfatal write failures. Standalone evidence is produced afresh on every test run, not copied from the historical `.audit/verification.json` manifest. No raw ledger or exception needs to be published.

## Publication gates

1. Review and merge the candidate through the normal workflow. Require fresh green Linux/macOS tests, typecheck and style on the exact release source. Existing CI covers both operating systems.
2. With explicit publication authorization, create and push tag `v1.4.0` on that approved source. This is a future maintainer action, not part of isolated verification. The GitHub-only tag workflow checks that the tag matches `package.json`, then runs style, typecheck and tests before creating the GitHub release. Its generated notes should be supplemented with the release notes above and actual verification links.
3. Confirm the GitHub release is stable, not a prerelease, and its tag/source/package version all agree. No registry publication or credentials are needed.
4. Only after publication, install the pinned source with `pi install git:github.com/markdlabrecque/pi-claude-subscription@v1.4.0` in the intended host, with the owner's authorization. Isolated verification is not permission to change personal settings. Record that host's actual versions and loader result separately.

No publication, tag push, live acceptance or personal installation was performed here. Live acceptance belongs to [#79](https://github.com/markdlabrecque/pi-claude-subscription/issues/79) and needs approval for each run.

## Disable and rollback

Unset `PI_CLAUDE_SUBSCRIPTION_AUDIT` or set it to `0` in the environment starting Pi, including request-scoped overrides, then restart Pi. This stops new audit records but does not delete existing private ledgers. Keep raw debug off and API fallback at `0` if separate API billing is unwanted.

The prior release is **v0.4.0**, source commit `8f8b45bf596225b19da28f6839e096cfe482ff7d`. To roll back after an authorized installation, stop Pi, then reinstall `git:github.com/markdlabrecque/pi-claude-subscription@v0.4.0` with `pi install` and restart. That revision has no audit feature and has a known Pi 1.4.0 loader defect, so it is not a known-working fallback on the pinned host. Disabling audit while retaining v1.4.0 is preferable for audit-only problems. For broader rollback, retain a separately verified prior installation/workflow rather than claiming v0.4.0 will load. Pinned tags do not advance through `pi update --extensions`.
